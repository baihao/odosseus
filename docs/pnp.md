# PnP 定位：原理 + 残差/雅可比/协方差

> 在线定位 [`odo/online.py`](../odo/online.py) 的核心几何步。给定一批 **3D 地图点** 与它们在当前帧的 **像素**，
> 反解相机（车）位姿 `(x, y, yaw)`，并给出这次解的 **协方差**（供 EKF 当测量噪声，见 [online_ekf.md](online_ekf.md)）。
> 实现：[`pnp_lin`](../odo/online.py#L181)（投影 + 残差 + 解析雅可比）与 [`solve_pnp`](../odo/online.py#L236)（稳健高斯-牛顿）。

---

## 0. PnP 在解什么（大白话）

**PnP = Perspective-n-Point**：已知一堆 3D 点的空间坐标，又知道它们各自落在当前图像的哪个像素上，反过来求「相机站在哪、朝哪」。

类比：你在房间里拍了张照片，事先知道 10 个物件（墙角、门把手…）的 3D 坐标，又能在照片里指出它们各自的像素。那么——你站哪、朝哪，才能让这些物件恰好投到照片里那些像素上？**唯一能对上的站位+朝向就是相机位姿。**

这里车在平面上跑，只解 **3 个量 `(x, y, yaw)`**（z/roll/pitch 从地图固定，或作为 `extra_dof` 小修正），比一般 6-DoF PnP 更稳。

- 像素对应哪来的：LightGlue 把当前帧匹配到地图帧的点。
- 3D 点哪来的：**在线定位**用建图阶段**预存的地图 3D 点**（`.npz` 里的 `X`，见 [map_build.md](map_build.md)）；离线 dt 标定实验 `refine_query` 则现场三角化。
- 候选 / 初值哪来的：见下面「两种候选来源」。

### 候选帧来源：常规定位 vs 重定位

`solve_pnp` 本身只解几何，**不负责找候选帧**。找候选有两条路（详见 [relocalise.md](relocalise.md)）：

| | 常规定位（每帧） | 重定位（丢失时） |
|---|---|---|
| 候选 prior | EKF 当前状态 `X` | MegaLoc 全局检索的 4 个候选 |
| 选帧方式 | [`Map.select`](../odo/online.py#L77)：用 `X` 的 (x,y) 在地图 **KD-tree** 查半径 `sel_radius=15 m` 近邻 → 朝向过滤 → 分趟取最近 → 安全帧优先，最多 `n_pass=3` 帧 | [`Reloc.candidates`](../odo/online.py#L469)：全局描述子相似度 top + 空间分散 ≥8 m，4 个 |
| 搜索半径 | 小（15 m） | 大（`reloc_r1=60 m`） |
| 做不做全局检索 | **否**（只查 KD-tree，便宜） | 是（全库比对，贵，仅丢失 ≥1 s 时） |

> KD-tree 在 [`Map.__init__` L74](../odo/online.py#L74) `cKDTree(T[:, :2, 3])` 构建：每相机一棵，索引该相机（经时间窗 + GT 精度过滤后）所有地图帧的 (x,y)。
>
> （离线 dt 标定的 `reloc_pnp.refine_query` 是另一条路径：候选来自离线检索 `pred.csv`，3D 点现场三角化，见 [retrieval.md](retrieval.md) / [map_build.md 附录 A](map_build.md)。）

### 多 pass 联合 PnP：3 帧不是分别定位，而是合并点云解一次

`Map.select` 每相机取**最多 `n_pass=3` 个地图帧**（同一地点不同圈经过的几帧，“趟/pass”），但**不是每帧各算一个位姿再平均**。[`measure`](../odo/online.py#L504) 把这几帧（及其它相机选中帧）**预存的 3D 点拼成一个大点云**，统一投影 + 匹配，`solve_pnp` **一次联合求解**出单个位姿（[L513-L526](../odo/online.py#L513) gather 拼接 → [L569](../odo/online.py#L569) 一次 solve）：
```python
for cam in cams:
    fr = fmap.select(cam, X, ...)        # ≤3 帧（3 个 pass）
    Xm, Dm = fmap.gather(cam, fr)        # 取这几帧的全部 3D 点 + 描述子
    Xs.append(Xm); Ds.append(Dm)
Xm = torch.cat(Xs); Dm = torch.cat(Ds)   # 所有 pass、所有相机的点合并成一堆
```
> 直觉：同一地点跑过 3 圈，3 圈的点合起来 = 更稠密、视角/光照更全的局部点云 → 匹配更鲁棒（“至少有一圈能对上当前帧”）。两阶段（粗→精）用的都是这同一堆合并点。

### 合并点云会有重复 3D 点吗？——会，但不显式去重

同一物理点（如某墙角）在 3 个 pass 里被**各自独立三角化**成 3 个坐标相近的点；`gather` 只是**原样拼接，没有 dedup / merge / 体素下采样**。代码靠三道被动机制化解重复，而非去重：

1. **匹配唯一性**（[`guided_match_mask` L283-L286](../odo/online.py#L283)）：mutual-best + 每个 query 关键点只配**一个**地图点。同一墙角的多个重复点投到同一处，那个 query 点只会被相似度最高的一个选中（`i[j]==arange`），其余重复点**配不上** → 多数重复在匹配阶段就被挤掉。
2. **几何冗余无害**：即便几个重复点各配到相邻 query 点都进了 PnP，它们是**同一几何约束重复几次**（同一空间点 ↔ 同一图像位置），只给该约束略加权，**不会把位姿拉偏**。
3. **RANSAC/内点剔除**（[`solve_pnp` L266](../odo/online.py#L266) `e < inl_px=3px`）：某个 pass 若三角化质量差/位姿偏，其重复点重投影误差大 → 判**外点**剔除，好的那份留下。

> 为什么不去重：实时（10 Hz）对上万点做近邻聚类/描述子合并开销大、收益小（上面三道已保证正确性）；且多 pass 的冗余本身是**鲁棒性特性**（不同光照/视角各留一份），强行 merge 反而丢多样性。另外每相机 **≤3 帧**（每趟取最近 1 帧，[L89](../odo/online.py#L89)）把重复倍数限制在 ~3，点云规模可控。

### 多相机刚体联合 PnP：7 个相机，解 1 个车身位姿

每帧有 7 个相机，它们各自选地图帧、各自匹配出 2D-3D 对应，**全部拼进一个 `obs` 一次解**（[L522](../odo/online.py#L522)）。但要点是：

> **优化变量不是 7 个相机 pose，而是一个共享的车身（base_link）pose `(x,y,yaw)`。** 7 个相机刚性固定在车上，相对位置（外参 `T_base_cam`）已知且不变，所以它们不是 7 个自由相机，而是**一个刚体上的 7 个视角**；相机 pose = 车身 pose × 已知外参，由车身 pose 唯一派生，不单独求解。

**每个相机的约束如何折算到车身位姿**（[`pnp_lin` L190-L196](../odo/online.py#L190)）：
```python
Xb = Rz(yaw)ᵀ (Xw − t)      # map 3D 点 → 车身(body)系，用【待优化的车身位姿】(t=x,y,z; yaw)
Xc = Rcb · Xb + tcb         # 车身 → 该相机系，用【该相机固定外参】Rcb,tcb = T_base_cam
uv = 投影+畸变(Xc)          # 该相机系 → 该相机像素（用该相机的 K、D）
```
- `t, yaw`：**待优化的车身位姿**，7 个相机共用这一个。
- `Rcb, tcb = cams.Rcb_np[ci]`（[L195](../odo/online.py#L195)）：第 `ci` 个相机的外参（标定常量，加载时从 `tf_static` 读）。
- `ci`：每个 3D 点带的**相机索引**，标明它来自哪个相机（[`measure` L527](../odo/online.py#L527) 由 `sl` 拼出），投影时用对应相机的外参 + 内参 `K/D`。

**求最优车身位姿 = 所有相机重投影误差一起最小化**（[`solve_pnp` L569](../odo/online.py#L569)）：
```
min_{x,y,yaw}  Σ_cam Σ_point  || 重投影误差(该相机,该点 | 车身位姿) ||²
```
每个相机的观测经自己的外参/内参进入**同一个**目标函数，雅可比 `∂(该相机像素)/∂(车身 x,y,yaw)`（[L211-L231](../odo/online.py#L211) 链式含该相机外参）把所有相机的证据都“拉”向同一个车身位姿。解出的 `(x,y,yaw)` 就是让 7 相机重投影误差整体最小的车身位姿——联合最优解（z/roll/pitch 从最近地图帧固定，只优化平面 3 自由度）。

> 好处：① 7 个视角覆盖车四周，几何约束远强于单相机，更准、更不易病态；② 天然一致，不存在“7 个相机各解一个 pose 再打架”；③ 外参 `T_base_cam` 是桥梁，把每个相机看到的 3D-2D 证据翻译成对**同一个车身位姿**的约束。这是标准的**多相机刚体联合 PnP**。

### 得到 2D-3D 对应：引导匹配（guided matching）

PnP 需要「3D 地图点 ↔ query 像素」的对应。[`measure`](../odo/online.py#L504) 做**两阶段引导匹配**（[L536](../odo/online.py#L536) 循环，`stage0` 半径 `r1`、`stage1` 小半径 `r2`）：

1. **投影求预测像素**：用当前假设位姿 `(R,t)` 把地图 3D 点经投影链投到图像，得预测像素 `uv_m`（[`Cams.project` L128-L144](../odo/online.py#L128)，链路同 §3）。`uv_m` 是搜索窗口的**圆心**。
2. **半径内找对应**（[`guided_match_mask` L283-L286](../odo/online.py#L283)）：
   ```python
   S = torch.where((d < radius) & ok_m, S, -2)   # 预测像素圈外的配对 → 相似度压成 -2（作废）
   best, j = S.max(1); _, i = S.max(0)
   good = (best > sim_thr) & (i[j] == arange)    # mutual-best + 相似度阈值
   ```
   `radius = r1 × 焦距/1000`（像素）。圈外或投影无效的配对被 `-2` 彻底作废 → 只有**预测像素 radius 内**、描述子互为最佳且够相似的配对，才成为一个 **匹配（match）**。

> **半径大小看 prior 多准**：常规定位 prior=EKF `X`（较准）→ `uv_m` 接近真匹配 → 小半径（~24）；重定位 prior=检索候选（可能偏）→ 大半径 `reloc_r1=60` 才兜得住真匹配。

### ⚠️ 匹配(match) ≠ 内点(inlier)：两道独立筛选

搜索半径卡的是**匹配**，不是内点。定位有两道关，别混：

| | 匹配半径 `radius`（来自 `r1`） | 内点阈值 `inl_px` |
|---|---|---|
| 判据 | 预测像素 ↔ query 特征点的**像素距离 < radius** | PnP 解出位姿后的**重投影误差 < 3 px** |
| 用谁的位姿 | **旧位姿 prior** 投影 | **PnP 新解** 重投影 |
| 值 | 重定位 60（宽，容忍 prior 偏差） | 3 px（严，固定） |
| 作用 | 决定能否成为**匹配**（`info['n_m1']`，[L564](../odo/online.py#L564)） | 决定匹配是否为**内点**（`info['n_inl']`，[L571](../odo/online.py#L571)）|
| 代码 | [`guided_match_mask` L283](../odo/online.py#L283) | [`solve_pnp` L266](../odo/online.py#L266) `inl = (e < inl_px)` |

- 距离 > radius → **连匹配都算不上**（不是“不算内点”——它根本没进 PnP）。
- 在 radius 内成为匹配的，**也未必是内点**：还要过 PnP 后“重投影误差 < 3 px”这关；半径内但 PnP 后误差大的（如错配、prior 带偏的几何）照样被判外点。

> 先过 `radius` 成为 **match**（宽松，用旧 prior 投影），再过重投影误差 `< 3 px` 成为 **inlier**（严格，用新解）——两道关，内点数 `n_inl` 与 radius 无关。

## 1. 核心工具：重投影误差

相机有已知的投影公式：给定位姿 + 一个 3D 点，能算出它**应该**出现在图像的哪个像素（“预测像素”）。

- 位姿猜对 → 预测像素落在实际观测像素上，误差为 0。
- 位姿猜错 → 预测像素与实际像素差一段，叫 **重投影误差**（单位：像素）。

**PnP 的本质就是：调整位姿，让所有点的重投影误差最小。** 误差最小时的位姿就是答案。

---

## 2. 残差 r —— 衡量的是像素

残差 = **预测像素 − 实际像素**，每个点一个二维向量 `(Δu, Δv)`，单位**像素**。代码 [`pnp_lin` L207](../odo/online.py#L207)：
```python
r = np.stack([fx*xd + cx, fy*yd + cy], 1) - uv
#   └── 预测像素（3D点投影+畸变→像素）──┘   └ 观测像素 ┘
```
点的“误差大小”是这个二维残差的长度（[`solve_pnp` L250/L265](../odo/online.py#L250)）：
```python
e = sqrt(r0[:,0]² + r0[:,1]²)     # 每点重投影误差 [px]
```
后面的内点阈值 `inl_px=3.0`、`huber=2.0`、残差方差 `s2` 都**以像素计量**。

## 3. 投影链：3D 点怎么变成像素

一个地图点 `Xw` 经过这几步落到像素（[`pnp_lin` L190-L207](../odo/online.py#L190)）：
```
Xw (map系3D点)
  │  减平移、乘旋转（由位姿 x,y,yaw 决定）         L190-L193
Xb (车 body 系)
  │  乘相机外参 Rcb, tcb（标定，固定）             L196
Xc (相机系3D点)
  │  除以深度 zc —— 透视投影                        L198
(x, y) 归一化像平面
  │  加畸变 k1,k2,p1,p2,k3                           L201-L203
(xd, yd)
  │  乘焦距 fx,fy、加主点 cx,cy                      L206-L207
(u, v) 像素  → 减观测 uv = 残差 r
```
雅可比 `J` 就是把这条链**对位姿求导**。

## 4. 雅可比 J —— “位姿动一点，像素残差变几像素”

`J` = 残差对位姿的偏导（灵敏度/斜率）。位姿 3 个量、残差 2 维 → 每个点一个 **2×3** 矩阵 `∂(Δu,Δv)/∂(x,y,yaw)`。

直觉：车往前挪 1 cm，某路标在图里横移几像素？这个“像素/cm”就是 J 的一项。J 越大=几何越敏感、约束越强。

**它是解析求导（链式法则）算的，不是数值差分** —— 快且精确。逐环（[`pnp_lin` L211-L231](../odo/online.py#L211)）：

| 环 | 导数 | 代码 |
|---|---|---|
| 1. 位姿 → body 点 | x/y（平移）取旋转矩阵负列；yaw（转角）取“叉乘 e_z”项 | [L211-L217](../odo/online.py#L211) |
| 2. body → 相机系 | 左乘常数外参 `Rcb` | [L222](../odo/online.py#L222) `dXc = Rcb @ dXb` |
| 3. 相机系 → 归一化 | 透视除法的商法则（含 `1/zc`） | [L224-L225](../odo/online.py#L224) |
| 4. 归一化 → 畸变坐标 | 畸变的 2×2 解析雅可比 `a11,a12,a21,a22` | [L227-L230](../odo/online.py#L227) |
| 5. 畸变坐标 → 像素 | 乘焦距 `fx,fy` | [L231-L232](../odo/online.py#L231) |

最终（[L231](../odo/online.py#L231)）：
```python
J = [ fx·(a11·dx + a12·dy),      # ∂u/∂(x,y,yaw)
      fy·(a21·dx + a22·dy) ]     # ∂v/∂(x,y,yaw)      形状 (点数, 2, 3)
```
`1/zc` 体现“越远的点，位姿变化引起的像素移动越小”；畸变项用 `k*/p*` 展开。开 `extra_dof` 时再补 z/roll/pitch 三列（[L218-L222](../odo/online.py#L218)）。全部 numpy 向量化，对所有点所有相机一次算完。

## 5. 求解：稳健高斯-牛顿 + 内点重拟合（[`solve_pnp`](../odo/online.py#L236)）

从初值 `p0`（检索给的）出发，迭代（[L248-L260](../odo/online.py#L248)）：
```python
for it in range(iters=8):
    r, ok, J = pnp_lin(...)                     # 残差 + 雅可比
    e = sqrt(Σ r²)                              # 每点像素误差
    w = Huber权重(e, huber=2.0) * ok * 内点掩码   # 大残差点降权（抗错配）
    A  = Jᵀ W J ;  dp = -(JᵀWJ)⁻¹ Jᵀ W r        # 高斯-牛顿步：位姿该挪多少
    p += dp
```
- **J 的第一处用途**：解 `dp = -(JᵀWJ)⁻¹ JᵀW r`，用斜率决定“把残差压小、位姿往哪挪”。反复几轮收敛。
- **Huber**（[L253](../odo/online.py#L253)）：对大残差点手下留情，别让个别错配主导。
- **内点重拟合**（[L252](../odo/online.py#L252)）：迭代过半时，把 `e < 3 px` 的点定为内点，后半程只用内点精解。

---

## 6. 协方差：这次解有多准（[L270-L272](../odo/online.py#L270)）

收敛后估不确定度（**J 的第二处用途**）：
```python
s2  = Σ(e_inl²) / (2n - nd)                 # 残差方差：内点像素误差²平均 [px²]
cov = (Jᵀ J)⁻¹ × s2                         # (x,y,yaw) 协方差 [m²/rad²]
```
为什么 `(JᵀJ)⁻¹ × 残差方差` 就是不确定度：

- **残差方差 `s2`（像素²）**：收敛后点还对不齐多少。残差大 = 观测噪 → 不该太自信 → 协方差大。
- **`(JᵀJ)⁻¹`**：把“像素层面的不确定”换算回“位姿层面”，并体现几何条件：
  - J 大（位姿一动像素就猛变，约束强）→ `JᵀJ` 大 → 逆小 → 协方差小（准）。
  - J 小（位姿动了像素几乎不变，病态，如点挤一堆/基线差）→ `JᵀJ` 小 → 逆大 → 协方差大（虚）。

即 **协方差 = 观测有多噪(s2) × 几何有多敏感的倒数((JᵀJ)⁻¹)** —— 标准最小二乘协方差公式。单位上像素²经 `(JᵀJ)⁻¹`（含焦距/几何）换算到 m²/rad²。只有内点参与，外点已被 Huber + 硬阈值剔除。

> 内点不足（`n<6`）→ 直接给巨大协方差 `eye(3)*1e6`（[L269](../odo/online.py#L269)），等价于“这次定位不可信”。这个 `cov` 随后 ×4 再加 floor 成为 EKF 测量噪声 `R`（见 [online_ekf.md](online_ekf.md)）。

## 7. 串起来

```
3D 地图点 + 它们在当前图的像素 + 粗初值
    │  [假设位姿] → 沿投影链算预测像素（L190-L207）
    │  预测像素 − 实际像素 = 残差 r [px]（L207）
    │  J = ∂r/∂位姿  解析链式求导（L211-L231）
    ├─ 解：dp = -(JᵀWJ)⁻¹ JᵀW r，Huber + 内点重拟合迭代（L248-L260）→ 收敛位姿 (x,y,yaw)
    └─ 估准：cov = (JᵀJ)⁻¹ × 残差方差（L270-L272）
              └ 几何敏感度 ┘  └ 观测噪声 px² ┘
```

**一句话：PnP 从检索给的粗初值出发，沿“3D 点→body→相机→透视→畸变→像素”投影链算残差（预测像素−实际像素，单位像素），J 是这条链对位姿 `(x,y,yaw)` 的解析雅可比（位姿动一点残差变几像素）；用 `dp=-(JᵀWJ)⁻¹JᵀWr` 做 Huber 稳健高斯-牛顿迭代 + 内点重拟合解出位姿，再用 `(JᵀJ)⁻¹×残差方差` 给出协方差（几何越敏感、残差越小越可信），该协方差即 EKF 的测量噪声来源。**
